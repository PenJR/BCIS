# BCIS Deployment Guide

## 1. Server PC prerequisites
- Windows PC/server with a static or reserved LAN IP.
- Node.js LTS installed for the API service.
- PostgreSQL server installed and running locally on the server PC.
- Local admin rights to install the API service and configure Windows Firewall.
- Ensure all client PCs can reach the server by LAN IP, not only localhost.

## 2. PostgreSQL setup
- Create the BCIS database and a dedicated application role.
- Keep PostgreSQL server-side only; Electron clients must never connect to PostgreSQL directly.
- Set the required environment variables on the server:
  - HOST
  - PORT
  - DATABASE_URL
  - JWT_SECRET
  - PG_DUMP_PATH
  - PG_RESTORE_PATH
  - BCIS_BACKUP_DIRECTORY
  - BCIS_RESTORE_DATABASE_URL
  - BCIS_ENABLE_RESTORE
- Store secrets only in the server's secure environment, not in the repository, installer, or source control.

## 3. Database migration and seed
From the server project directory:
- npm install
- npm run build
- npm run migrate

Optional demo seed for a test deployment only:
- set BCIS_DEMO_SEED=true
- set BCIS_DEMO_PASSWORD
- npm run seed:demo

Do not run demo seeding in production unless the environment is intentionally configured for it.

## 4. API configuration and startup
- Bind the Fastify API to the LAN interface using HOST=0.0.0.0 and the chosen PORT.
- Start the API from the server machine with the configured environment variables loaded.
- The API should be reachable on the server LAN IP, for example http://SERVER-LAN-IP:PORT.

## 5. Windows Firewall and LAN requirements
- Allow inbound TCP traffic on the API port used by the server.
- Allow PostgreSQL-only traffic on the database port only from the server itself and approved local admin hosts.
- Keep the database inaccessible from the client workstations.
- Ensure the server PC has a stable LAN IP or DHCP reservation so client configuration remains valid.

## 6. Electron client installation
- Install the signed production MSI/EXE generated by electron-builder on each client PC.
- Do not install PostgreSQL or database credentials on the clients.
- Keep the Electron app pointed at the server API URL, not localhost.

## 7. Configuring the client API address
Create or update the app runtime config file in the user data directory for the installed app:

```json
{
  "apiBaseUrl": "http://SERVER-LAN-IP:3000"
}
```

This file is read by the packaged Electron client at startup. It is the configurable server/API address and should not contain database credentials or secrets.

## 8. Backup and restore considerations
- Store backups on the server filesystem in a protected location.
- Use PostgreSQL client tooling installed on the server host.
- Keep backup directories access-controlled and backed up separately.
- Use a restore-only database for any non-production recovery testing.

## 9. Basic 3-PC connection verification
1. Confirm the API responds on the server LAN IP from PC 1.
2. Confirm the API responds from PC 2 and PC 3 using the configured client API address.
3. Confirm each Electron client can log in, load data, and perform a basic read action.
4. Confirm no client is directly connecting to PostgreSQL.

## 10. Shutdown and restart procedure
- Stop the API process on the server.
- Stop or pause PostgreSQL only when required for maintenance.
- Restart PostgreSQL first if needed, then start the API.
- Verify health endpoints and application access before returning the environment to normal use.
